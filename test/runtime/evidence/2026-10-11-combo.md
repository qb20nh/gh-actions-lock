# Implemented malformed-lock workaround combo

Recorded on 2026-10-11 KST (2026-10-10 UTC). Upstream
[#125](https://github.com/github/gh-actions-lock/issues/125) remains open: the
hosted service itself still needs to reject malformed lock YAML. These checks
establish repository-controlled consumer gating and frozen dependency validation.

## Implementation

The [reusable validator](../../../.github/workflows/lock-validation.yml) has no
actions, container, or services. Test, dependency review, release, M6 validation,
and uploaded-asset verification consumers require its success. It builds the
trusted verifier at immutable commit
`568368f04df85de69e9194610f87c4f9af58b8bf`, fetches the exact caller revision,
and materializes raw Git blobs with the trusted helper. It executes no candidate
scripts, filters, hooks, or build instructions.

`--require-lockfile` rejects missing, empty, nonregular, and repository-path
symlinked locks. `--verify-frozen` requires a lock, remains read-only, and inspects
the actual defining-commit action/workflow graph. Mutable refs, missing discovered
edges, invalid manifests, and inconclusive verification reject. Declared
`docker://` action uses require a full SHA-256 digest. Dockerfile images, job and
service containers, and arbitrary shell downloads remain outside this graph.

The [policy workflow](../../../.github/workflows/lock-policy.yml) publishes the
`Lock policy` commit status on the exact head and merge revisions for PRs, and
on the exact push or merge-group revision. Its trusted base workflow reads
candidate source as data. A status tied only to the GitHub Actions app does not
prevent another authorized workflow from publishing the same context; stronger
ownership requires an independent reviewer or separately administered validator.

Remote action refs throughout the active graph use full SHAs. The release
composite is [vendored](../../../.github/actions/gh-extension-precompile/UPSTREAM.md)
with pinned setup-go and attestation children, including the predicate subaction.
Earlier mutable-ref runtime probes are archived under `test/runtime/workflows/`
so their negative controls do not belong to the active production graph.

## Local checks and activation

Formatting, vet, release-script checks, the full Go race suite, and 34 stub
scenarios passed. Protection tests include seven actual-binary staged-hook
controls; five raw-materialization tests cover export attributes, checkout
encoding/filters, file modes, symlinks, reserved paths, and symlink traversal.
`make test` includes both protection and materialization checks.

The local hook is enabled through `core.hooksPath=.githooks`. It checks raw
index blobs, including partially staged files, offline coverage, and recorded
full-SHA refs. Authenticated complete-graph verification is an explicit opt-in.

The exact eight-entry allowlist, CODEOWNERS, and idempotent protection setup are
prepared in [actions-protection.md](../../../docs/actions-protection.md).
Repository administration is **not applied**: the current connector exposes no
administration writes, and the managed shell has no working administration
credential. The script's read-only preflight failed before any settings write.
Activation also requires deploying the matching validator and successful policy
status on the branch being protected. Default branches remain unchanged.
